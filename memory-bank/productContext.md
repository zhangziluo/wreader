# Product Context — 为什么会有这个项目

> 回答"为什么做、给谁用、体验目标是什么、为什么这样取舍"。最后更新：2026-09-23。

## 要解决的真实问题

1. **想读原著但读不下去**：中文用户读英文书，卡生词、卡长句，读两页就放弃。
   → 中文/英文/双语三种视图随时切换，`v` 随手查词并入生词本。
2. **图形阅读器太重**：要开窗口、要账号、要同步、要导入向导。
   → 终端一条命令开读，进度自动落盘，退出时打印一行摘要。
3. **下载站的 txt 很脏**：编码杂（GB2312 / UTF-16 / 带 BOM / 损坏）、文件名形如
   `《书名》（校对版全本）作者：某人.txt`。→ 导入时自动识别编码、宽编码优先、清洁书名作者。
4. **阅读数据是黑盒**：不知道自己到底读了多少、能不能坚持。
   → 时长统计、每日热力图、连续阅读天数、**48 个成就**（事件驱动解锁，含实时按键彩蛋与隐藏成就）。
5. **整本机翻太贵**：→ **按章缓存**：看过一次就不再花钱；`t`（翻当前屏）故意不写缓存。
6. **读到好句子想记下来**：纸上/手机上记笔记会离开阅读界面，或者干脆忘了记在哪。
   → 屏内选字（`m` + `y`）→ 笔记面板写批注 → **落盘成 markdown**（`~/.wreader/notes/`），
   下次 `werd notes <id>` 逐条翻看，或直接拿编辑器打开那个文件。

## 目标用户

- **主要**：在 macOS / Linux 终端里工作、习惯键盘操作、想看中英文长篇小说的开发者。
- **次要**：想用命令行管理生词并导出 Anki 的语言学习者。
- **次要**：在**手机终端**（Termux 等）上读书的人 —— 没有实体键盘，靠触摸滑动 / 鼠标滚轮逐行翻页；
  音量键可用终端自身的映射翻页。

## 用户体验目标

- **打开就能读**：`import` → `list` → `read <id>`，三步，无向导。
- **按键不用背**：底部提示栏常驻显示全部快捷键。
- **不丢进度**：`q` / `Q` / `Ctrl-C` 都会保存；`reader.auto_save_interval`（默认 60 秒）再兜一层。
- **不打扰**：生词只加下划线；翻译/成就/错误都走"几秒后自动消失"的短消息。
- **笔记不丢**：`Ctrl+S` / `Esc` 落盘成 markdown；编辑区每 30 秒留一份草稿，
  崩溃、掉电、`Ctrl-C` 都不丢字；换终端、换机器、`ssh` 过去都能接着看（靠文件锁串行化）。
- **尊重终端**：正文按终端宽度**自动换行**；配色**跟随终端主题与透明背景**；
  窄屏也不会出现"整行文字凭空消失"（2026-09 修复，见 `activeContext.md`）。
- **手机上也能读**：手指按住上下拖动 = 逐行滚动（**向上滑往后读、向下滑往前看**，拖一行走一行），
  鼠标滚轮同理；一格滚几行可配（`reader.wheel_scroll_step`，默认 1），
  不想要手势可以关掉（`reader.touch_scroll`）。
- **坏数据不致命**：坏文件只进 `failed`；生词本/成就文件损坏只提示一句，绝不让阅读崩掉。

## 关键产品决策与理由

| 决策 | 理由 |
| --- | --- |
| 导入时把正文统一转成 UTF-8 | 读取、定位、翻译只用一种编码，逻辑最简单、出错面最小 |
| `book_id` = 正文内容 SHA-1 前 12 位 | 与文件名无关，重复导入天然被识别 |
| 以**源行**为分页与进度单位 | 行号、书签、章节起点、`lines_read` 共用一套坐标，永不错位 |
| 双语视图下一个源行可占多条屏幕行 | 折行与"原文+译文"都靠它，分页仍按源行算 |
| 翻译缓存以**章**为单位 | 粒度够粗（省钱、可断点续翻）又够细（不必整本翻完才能读） |
| 译文文件名固定 `_en` | 历史命名；容器里装的其实是 `translator.target_language` 的结果（已知包袱） |
| 成就条件写纯文本表达式 | 用户可自己加成就，无需改代码 |
| 成就再叠一层"事件记录" | 表达式只能算索引里有的东西；"打开过几天""周末读了多少秒""按行号去重后的字数"必须随事件记下来，所以先记进 `achievements.json`，再由表达式判定 |
| 笔记用 markdown 而不是 JSON | 笔记是给人看的内容（可能很长、含中文）。markdown 更适合"直接拿编辑器读/改"，`--export` 也就成了一次复制 |
| `notes/index.json` 只做**派生**缓存 | 避免"两处记条数"的经典漂移：条数永远从 `.md` 里数出来，索引删掉还能自愈 |
| 30 秒自动保存做成"**崩溃草稿**" | 每 30 秒追加一条正式笔记会重复记账（`save_note` 是追加语义）；草稿只负责"不丢字"，提交仍由用户动作触发 |
| 文件锁抽成 `wreader/lock.py` 共用 | 成就状态与笔记索引都要"读-改-写"串行化（多终端 / 多机器）。一份实现才不会各自跑偏 |
| 阅读中的成就通知做成**右上角 5 秒牌子**（非阻塞、不吞按键） | 规格要"屏内通知"，而读者此刻正在读书：弹一个等按键的窗口会打断沉浸感，还可能吃掉一个按键。改成随帧绘制的时间窗后，体验上等同于"墙上亮了一下" |
| 阅读器**只在越过成就门槛时**才写状态文件 | 一次判定 = 文件锁 + 重写状态 + 读书库；按一次键写一次盘不可接受。门槛表直接从定义文件解析，所以用户自加的成就同样实时生效 |
| 地理成就**默认联网、可一键关闭** | 位置成就没法离线算出来，但"查 IP"是隐私敏感操作。默认开（否则这些成就形同不存在）+ `stats.geo_lookup=false` 一键完全离线，把选择权交给用户 |
| 意外中断的恢复提示**只认同一本书** | 现场是临时的、按书隔离的；跨书套用行号会让用户跳到莫名其妙的位置。宁可少问一次 |
| 老成就名保留 id 只改显示名 / 新增成就只加 id | 解锁记录、`library.json` 里的旧数据、README 举例都按 id 说话；改名不动 id，老用户一个成就都不会丢 |
| 一切皆纯文本存储 | 用户能自己修数据、备份、用 `jq` 处理 |
| 配置用 TOML + section 结构 | 比扁平 JSON 更可读，且能自动迁移旧配置 |
| 触摸拖动按「1 行 = 1 行」换算 | 手机阅读的直觉是内容跟手；按屏幕行算比"整屏 / 半屏"细得多，正好解决"翻页丢上下文" |
| 向上滑 = 往后读、滚轮下 = 往后读 | 与主流手机阅读器一致（内容跟手），两种输入的"往后"方向也统一 |
| 滚轮 / 触摸的按键位"有就用、不猜" | 猜出来的位会与 `BUTTON_SHIFT` 撞车，把 shift+点击误判成滚动；宁可少一个方向也不误判 |

## 迁移与兼容承诺

- 工具改名前的数据目录 `~/.nr` 会在首次运行时**整体搬迁**到 `~/.wreader`；两者都存在时只认新目录。
- 旧扁平 `config.json` 第一次加载设置时自动折叠进 `settings.toml` 的对应 section，
  原文件改名为 `config.json.bak` 保留。
- 旧环境变量 `$NR_HOME` / `$NR_NOVELS_DIR` 仍有效，但仅在没设新名字时读取。
- 旧 `vocab.json` 的 `{"words": [...]}` 包装结构、`book_title` / `created` 旧字段名仍能读入。
- **成就解锁记录**：旧版把解锁写在 `library.json` 的 `achievements.unlocked` 里（三种历史写法都认）。
  第一次读成就状态时**自动迁移**一次到 `~/.wreader/achievements.json`，之后旧位置不再被读取 ——
  老用户的解锁一个都不会丢。
- **笔记没有历史包袱**：Phase 1+2 的笔记只存在内存里，退出即失，所以没有"旧格式"要迁移；
  从 Phase 3 起一律写在 `~/.wreader/notes/`（markdown + 派生索引 + 草稿）。
