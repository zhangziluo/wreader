# Product Context — 为什么会有这个项目

> 回答"为什么做、给谁用、体验目标是什么、为什么这样取舍"。最后更新：**2026-09-25**。

## 要解决的真实问题

1. **图形阅读器太重**：要开窗口、要账号、要同步、要导入向导。
   → 终端里一条命令开读，进度自动落盘，退出时打印一行摘要。
2. **下载站的 txt 很脏**：编码杂（GB2312 / UTF-16 / 带 BOM / 损坏）、文件名形如
   `《书名》（校对版全本）作者：某人.txt`。→ 导入时自动识别编码、宽编码优先、清洁书名作者。
3. **阅读数据是黑盒**：不知道自己到底读了多少、能不能坚持。
   → 时长统计、每日热力图、连续阅读天数、**48 个成就**（事件驱动解锁，含实时按键彩蛋与隐藏成就）。
4. **手机上没有顺手的终端阅读方式**：Termux 里没有实体键盘。
   → 触摸拖动 / 鼠标滚轮**逐行**滚动（不是整屏跳），一格滚几行可配。
5. **数据应当属于用户**：不能锁在某个数据库或云服务里。
   → 一切皆纯文本（JSON / TOML / UTF-8），随时能手改、备份、`jq` 处理。

> ⚠️ **2026-09-25 已移除的三个功能**（历史动机记录在此，**不要再照着做**）：
> 「想读原著但读不下去」→ 双语视图 / 查词 / 生词本；「整本机翻太贵」→ 按章翻译缓存；
> 「读到好句子想记下来」→ 标记模式 + 笔记面板 + markdown 落盘。
> 现在这些**既不是待办也不是遗留缺陷**，而是被明确砍掉的产品边界（见 `projectbrief.md` 非目标）。

## 目标用户

- **主要**：在 macOS / Linux 终端里工作、习惯键盘操作、想看中文长篇小说的开发者。
- **次要**：在**手机终端**（Termux 等）上读书的人 —— 主要靠触摸滑动逐行翻页；
  音量键可用终端自身的映射翻页。
- **次要**：老版本用过翻译 / 生词本 / 笔记的用户 —— 他们记下的数据不会被删，成就进度照常。

## 用户体验目标

- **打开就能读**：`import` → `list` → `read <id>`，三步，无向导。
- **按键不用背**：`?` 是完整快捷键帮助页，底部提示栏常驻显示常用键。
- **不丢进度**：`q` / `Q` / `Ctrl-C` 都会保存；`reader.auto_save_interval`（默认 60 秒）再兜一层；
  意外中断后重开同一本书会问一句要不要接着读。
- **不打扰**：成就解锁走"几秒后自动消失"的屏内牌子（非阻塞、不吞按键）。
- **尊重终端**：正文按终端宽度**自动换行**；配色**跟随终端主题与透明背景**；
  窄屏也不会出现"整行文字凭空消失"（2026-09 修复，见 `activeContext.md`）。
- **手机上也能读**：手指按住上下拖动 = 逐行滚动（**向上滑往后读、向下滑往前看**，拖一行走一行），
  鼠标滚轮同理；一格滚几行可配（`reader.wheel_scroll_step`，默认 1），
  不想要手势可以关掉（`reader.touch_scroll`）。
- **坏数据不致命**：坏文件只进 `failed`；成就状态 / 书库索引损坏只提示一句，绝不让阅读崩掉。

## 关键产品决策与理由

| 决策 | 理由 |
| --- | --- |
| 导入时把正文统一转成 UTF-8 | 读取、定位、搜索只用一种编码，逻辑最简单、出错面最小 |
| `book_id` = 正文内容 SHA-1 前 12 位 | 与文件名无关，重复导入天然被识别 |
| 以**源行**为分页与进度单位 | 行号、书签、章节起点、`lines_read` 共用一套坐标，永不错位 |
| 翻页保留几行上下文（`reader.page_overlap`，默认 3） | 用户要求"翻页时上下保留三行前面的文字"；项目约定阅读行为都走 `SCHEMA`，不做魔数 |
| 屏顶坐标 = `(源行号, 段内偏移)`，偏移**只作显示态** | 只记源行号时，一屏中途被折行截断的"半截段落"会被整个跳过。**不落库**是为了守住「行号坐标唯一」这条硬约束，代价是重开书从行首开始 |
| 成就条件写纯文本表达式 | 用户可自己加成就，无需改代码 |
| 成就再叠一层"事件记录" | 表达式只能算索引里有的东西；"打开过几天""周末读了多少秒""按行号去重后的字数"必须随事件记下来，所以先记进 `achievements.json`，再由表达式判定 |
| 字数按**行号区间**去重（`Pager.read_ranges`，挂在 `move_to()` 这个唯一位移入口） | 只记行数换算不出字数，只记总字数会因回翻重复累加；行区间是唯一同时满足"去重"与"行号坐标唯一"的表示 |
| 阅读中的成就通知做成**右上角 5 秒牌子**（非阻塞、不吞按键） | 规格要"屏内通知"，而读者此刻正在读书：弹一个等按键的窗口会打断沉浸感，还可能吃掉一个按键 |
| 阅读器**只在越过成就门槛时**才写状态文件 | 一次判定 = 文件锁 + 重写状态 + 读书库；按一次键写一次盘不可接受。门槛表直接从定义文件解析，所以用户自加的成就同样实时生效 |
| 地理成就**默认联网、可一键关闭**（`stats.geo_lookup`） | 位置成就没法离线算出来，但"查 IP"是隐私敏感操作。默认开 + 一键完全离线，把选择权交给用户 |
| 意外中断的恢复提示**只认同一本书** | 现场是临时的、按书隔离的；跨书套用行号会让用户跳到莫名其妙的位置。宁可少问一次 |
| 老成就名保留 id 只改显示名 / 新增成就只加 id | 解锁记录、`library.json` 里的旧数据、README 举例都按 id 说话；改名不动 id，老用户一个成就都不会丢 |
| 一切皆纯文本存储 | 用户能自己修数据、备份、用 `jq` 处理 |
| 配置用 TOML + section 结构 | 比扁平 JSON 更可读，且能自动迁移旧配置 |
| 触摸拖动按「1 行 = 1 行」换算；向上滑 = 往后读、滚轮下 = 往后读 | 手机阅读的直觉是内容跟手；与主流手机阅读器一致，"往后"方向两种输入也统一 |
| 滚轮 / 触摸的按键位"有就用、不猜" | 猜出来的位会与 `BUTTON_SHIFT` 撞车，把 shift+点击误判成滚动；宁可少一个方向也不误判 |
| 文件锁抽成 `wreader/lock.py` 共用 | 成就状态与书库索引都要"读-改-写"串行化（多终端 / 多机器），一份实现才不会各自跑偏 |
| **2026-09-25：翻译 / 生词本 / 笔记整体删除**（`translator.py`、`translate/` 8 个文件、`vocab.py`、`notes.py` 及对应子命令、键位、测试、校验脚本、文档全部移除） | 维护面太大（六家翻译引擎 + 生词本 + 笔记面板，另有它们在阅读器里的视图/面板/缓存 UI），而产品的核心价值是"读"。删掉之后包内 `.py` 从 **22** 个降到 **11** 个、测试从 **832** 降到 **559** 项、校验脚本从 10 个降到 **8** 个；`git diff HEAD --numstat` 实测这一轮共 **-10,649 / +599** 行（含文档） |
| **老数据文件只读计数，既不删也不迁移** | `vocab.json` / `notes/*.md` 是用户自己记的东西，程序没有资格删或改。只读数一遍就够喂成就指标，老用户的进度一个都不掉；用户想清空，自己删文件即可 |
| **老配置键只警告、不报错**（`werd config` 列出设置时逐键打 `warning: unknown setting '...' is ignored`，见 `cli._print_config`） | 老 `settings.toml` 里留着 `translator.*` / `translate.*` / `vocab.*`。报错会逼用户手改文件，静默忽略又让人以为设置生效了 —— 一行警告是唯一诚实的做法 |

## 迁移与兼容承诺

- 工具改名前的数据目录 `~/.nr` 会在首次运行时**整体搬迁**到 `~/.wreader`；两者都存在时只认新目录。
- 旧扁平 `config.json` 第一次加载设置时自动折叠进 `settings.toml` 的对应 section，
  原文件改名为 `config.json.bak` 保留。
- 旧环境变量 `$NR_HOME` / `$NR_NOVELS_DIR` 仍有效，但仅在没设新名字时读取。
- 老 `vocab.json` 的 `{"words": [...]}` 包装结构与 `book_title` / `created` 旧字段名**仍能读入**
  （只用于数条目，见 `stats.vocab_legacy_count`）。
- **成就解锁记录**：旧版把解锁写在 `library.json` 的 `achievements.unlocked` 里（三种历史写法都认）。
  第一次读成就状态时**自动迁移**一次到 `~/.wreader/achievements.json`，之后旧位置不再被读取 ——
  老用户的解锁一个都不会丢。
- **老配置键**不再认识（`config.Config.unknown`），`werd config` 列出设置时逐键打一行
  `warning: unknown setting '...' is ignored`，**不改写、不删除**用户的 `settings.toml`。
- **老数据文件不动**：`vocab.json`、`notes/` 只读；老译文缓存目录 `cache/<book_id>/` 已无代码读取，
  用户可自行删除（README 已说明）。
